Минимальное развитие данных без новой CMS

В переданном архиве нет сервера и административной панели. Редактировать данные внутри минифицированного JS вручную рискованно. Исправления в пакете не добавляют новую CMS. Рекомендуемая следующая итерация в исходном репозитории — отдельный валидируемый JSON/TS-реестр, из которого строятся страницы и sitemap.

Для каждого объекта нужны стабильные id и slug, название, тип объекта, район/город, адрес и статус его проверки, координаты с источником и точностью, фото с источником и правами, контактные URL, типы размещения, диапазон вместимости, сезонность и цены с единицей тарифа. Для каждого спорного признака хранить `true / false / null`, `sourceUrl`, `checkedAt`, `checkedBy`; null означает неизвестно. Отсутствие цены — null, не 0. Рейтинги и отзывы — отдельные сущности с источником, датой и числом оценок; до проверки не публиковать.

Проверки при редактировании: обязательные id/slug/name; уникальность id и URL; ASCII slug; нормализация URL; допустимые схемы https/http для внешних ссылок и tel для реального телефона; исключение javascript/data; координаты только в допустимых диапазонах и с источником; цена > 0 и единица измерения; вместимость min ≤ max; дата проверки не в будущем; подтверждение прав на фото. Для публикации подробной карточки нужны адрес/локация и действующий способ связи либо явно объяснённое отсутствие контакта.

Публикация: данные → валидация → отбор категорий → HTML/метатеги/JSON-LD → sitemap → проверки. При изменении slug создавать однозначный 301, исключать циклы и цепочки. Пустая категория остаётся редакционным черновиком/noindex. Индексировать комбинации фильтров автоматически нельзя.

Быстрое повышение конверсии: сначала проверить и заполнить контакты 23 кратких карточек без сайта. Затем выпустить отдельные страницы для уже существующих кратких объектов, когда будет достаточно проверенных данных. Это расширяет каталог без фиктивных баз и бессодержательных URL.
