План развития на 90 дней

Старт — после проверки пакета на staging и отдельного разрешения на production-деплой. Численные цели по трафику и конверсии устанавливать после базового замера; частотность и гарантированный прирост здесь не выдумываются.

|---|---|---|---|
| Дни 1–7 | Техническая оптимизация: получить исходный репозиторий, проверить TLS, Apache, proxy, редиректы, статусы, доступ роботов; перенести патч в компоненты исходного проекта | P0 | Сборка и тесты проходят; нет циклов редиректов, soft-404 и 5xx; все канонические URL отвечают 200 |
| Дни 1–7 | Аналитика: проверить владельца счётчика 113576337, приём listing_view/base_view/filter_apply/external_site_click/map_open; создать цели в Метрике | P0 | Одна цель на фактическое действие; base_id без пользовательских контактов; контроль в режиме отладки |
| Дни 1–14 | Качество данных: сверить 10 подробных карточек и критичные удобства, цены/единицы/даты; разобрать конфликты services/theme/table/accommodations | P0 | У каждого опубликованного факта источник и дата; число противоречий и ложных совпадений стремится к 0 |
| Дни 8–21 | Техническая оптимизация: проверить sitemap и noindex в Яндекс Вебмастере/GSC; оценить трафик исторических страниц перед публикацией изменений индексации | P1 | В sitemap только канонические полезные страницы; фильтры не множат индекс; важные URL доступны |
| Дни 8–30 | Оптимизация карточек: заполнить проверенные контакты 23 кратких объектов без сайта; добавить телефоны/мессенджеры только после подтверждения | P1 | Доля объектов с рабочим контактом; external_site_click и будущие phone_click/messenger_click на 100 base_view |
| Дни 8–30 | Конверсия: проверить подбор на мобильных с реальными пользователями; уточнить подписи фильтров и сравнения; не создавать фиктивное бронирование | P1 | Время до подходящей карточки, доля listing_view→base_view→контакт; доля поиска без результатов |
| Дни 15–35 | Расширение категорий: проверить A-frame, личные сауны/бассейны, беседки/мангалы, отдых на день и реальные новогодние условия; переоткрывать существующие URL после наполнения | P1 | Число проверенных подходящих объектов на страницу; поисковые показы и доля переходов к контактам по категории |
| Дни 15–45 | Оптимизация карточек: создать отдельные страницы для существующих кратких объектов с достаточными фактами, реальными фото и контактом; уникальные slug без удаления записей | P1 | Доля полноценных карточек; валидность обязательных полей; переходы и контакты с новых карточек |
| Дни 21–45 | Внутренняя перелинковка: связать карточки с проверенными категориями, добавить альтернативы по удобствам, затем по подтверждённым координатам | P1 | Все полезные страницы достижимы обычными ссылками; отсутствуют битые и нерелевантные переходы |
| Дни 21–45 | Скорость: измерить LCP/INP/CLS на реальных устройствах, вернуть исходный сборщик, разделить маршруты и тяжёлые части приложения | P1 | Полевой p75: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 при достаточном количестве визитов; иначе лабораторный профиль |
| Дни 30–60 | Изображения: подтвердить права, подготовить AVIF/WebP и srcset по ширине, локально хранить только разрешённые фото, проверить размеры галерей | P1 | Снижение байтов изображения на карточку и LCP без заметной потери качества |
| Дни 30–60 | Контентные подборки: «как выбрать базу с ребёнком», «бассейн, чан и купель: что уточнить», «как сравнить итоговую цену» с редакционной проверкой | P2 | Реальные переходы статья→категория→карточка→контакт; качество ответов, а не объём текста |
| Дни 30–60 | Семантика: собрать запросы Вебмастера/GSC и реальные вопросы посетителей; проверить пары /romanticheskiy-otdyh/ и /domiki-na-dvoih/, другие пересекающиеся интенты | P1 | Снижение каннибализации по фактическим данным; устойчивый канонический URL для интента; отсутствие новых пустых страниц |
| Дни 45–75 | Расширение географии: Воткинский/Сарапульский районы и другие локации по проверенным объектам; Глазов — только после появления достаточных данных | P2 | Полезность выдачи по локации; точность района/адреса/маршрута; конверсия в обращение |
| Дни 45–75 | Аналитика: добавить phone_click/messenger_click/booking_click только при появлении соответствующих реальных действий; favorite_add — при согласованном внедрении избранного | P2 | Корректный base_id, отсутствие ПД в событиях и дублей; события соответствуют существующим кнопкам |
| Дни 45–90 | Внешнее продвижение: редакционные партнёрства с региональными туристическими ресурсами и владельцами; актуальные упоминания каталога; без покупки спам-ссылок и накрутки ПФ | P2 | Целевые переходы и обращения с площадок, релевантные упоминания и ссылки, качество трафика |
| Дни 60–90 | Рейтинг: оценить доступность реальных отзывов и право их использования; определить воспроизводимую модель только при достаточных данных | P2 | Проверяемый источник, число и свежесть отзывов; открытая методика; независимость качества и соответствия сценарию |
| Дни 76–90 | Итог: сравнить базовый и текущий периоды с учётом сезонности; устранить сценарии без результатов; приоритизировать следующий квартал | P1 | Органические обращения к объектам, CTR карточек, конверсия в контакт, полнота каталога и точность подбора |

Для экспериментов фиксировать базу и формулу: CTR карточек = base_view / listing_view, конверсия обращения = посетители с контактом / посетители карточек. По возможности считать уникальных посетителей и сессии, а не делить сырые события с повторами. Отдельно отслеживать объекты и категории: рост посещаемости без роста подходящих переходов и обращений не является достаточным успехом.
