# Сборка для хелп18.рф

## Загрузка на REG.RU

Архив `help18-regru-production.zip` содержит только готовые файлы сайта. Распакуйте его содержимое в корень привязанного домена (обычно public_html), без дополнительной папки. В этом корне должны оказаться index.html, .htaccess, robots.txt, sitemap.xml, urls-for-indexing.txt и assets/. Проверьте, что файловый менеджер загрузил скрытый файл .htaccess. Node.js на хостинге не требуется.

.htaccess рассчитан на Apache 2.4 с mod_rewrite и разрешённым AllowOverride. Такой конфигурацией выполнена локальная проверка. Если домен обслуживается только Nginx и .htaccess игнорируется, настройте сервер: index index.html; try_files $uri $uri/ =404; error_page 404 /404.html; перенаправления /index.html и /politika-konfidencialnosti/ должны вести на основные адреса. Общий fallback на главную не нужен: все реальные страницы уже имеют собственный index.html.

Проверка после загрузки: откройте /ceny/, /narkolog-na-dom/, /kontakty/ напрямую и обновите их. «Исходный код страницы» должен содержать весь текст. Неизвестный адрес должен возвращать HTTP 404. Для повторной массовой проверки из каталога исходников: `CHECK_BASE_URL=https://xn--18-mlcyu7a.xn--p1ai python scripts/validate.py` (Python 3). Локальные проверки не подтверждают фактическую настройку вашего аккаунта REG.RU.

## Повторная сборка

Проверено с Node.js 24.19.0, npm 11.9.0. Из каталога проекта:

```sh
npm ci
npm run build
npm run lint
npm run type-check
```

Результат находится в out/. Скрипт build сначала собирает клиентский React, затем генерирует HTML всех маршрутов из src/router/config.tsx, SEO-теги, robots, sitemap и список URL. Домен берётся из .env.production; кириллический домен автоматически переводится в punycode. Сборка прекращается при отсутствующем домене, повторяющихся title/description и неполных публичных страницах.

HTML получен из исходных компонентов, а не из сокращённого SEO-шаблона. hydrateRoot подключает обработчики к готовой разметке. Добавляя будущие статьи, категории и карточки объектов, создавайте настоящие компоненты и маршруты с уникальными метаданными: генератор включит их при сборке. В исходном архиве таких отдельных страниц нет.

## Яндекс и существующие интеграции

В исходном архиве нет ни yandex-verification, ни номера Метрики, ни .env с этими значениями. Рабочие коды невозможно восстановить из отсутствующих данных. Для подключения задайте реальные значения в .env.production и пересоберите:

```dotenv
VITE_PUBLIC_YANDEX_VERIFICATION=код_из_Яндекс_Вебмастера
VITE_PUBLIC_YANDEX_METRIKA_ID=номер_счётчика
```

При заданном счётчике сборка добавляет один noscript-пиксель в body вне root. Скрипт Метрики загружается одной точкой входа в src/lib/analytics.ts с защитой от повторного подключения и стандартной очередью ym. Проверка Вебмастера добавляется в head каждой страницы. Текущая сборка не содержит вымышленных кодов и не ведёт учёт в Метрике.

Формы и адрес https://readdy.ai/api/form/dbfkamgob50fdbpndc8g сохранены. Реальные заявки при проверке не отправлялись. Необязательные переменные CRM и мессенджера сохранены. Изображения Readdy, Google Fonts и CDN иконок используют прежние внешние адреса. Среда запрещает доступ к этим доменам (403 от сетевого прокси), поэтому их доступность и визуальная загрузка не подтверждены. Все локальные assets проверены. Исходные демонстрационные реквизиты и заготовки юридических документов не переписывались.
